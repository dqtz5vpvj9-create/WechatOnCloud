# 设备伪装与风控应对

> 返回 [← README](../README.md)

本页说明上游已有的环境处理行为。本 fork 新增的措施和可验证边界见[微信启动环境过滤](runtime-environment.md)。这些措施的风控效果未取得腾讯确认，不能保证清除全部可观察特征或消除账号风险。

## 背景

上游 [#27](https://github.com/Gloridust/WechatOnCloud/issues/27) 和 [#38](https://github.com/Gloridust/WechatOnCloud/issues/38) 出现过安全原因重新登录的用户报告。报告能够证明用户遇到了限制，无法单独确定触发它的具体环境特征。

项目让每个实例拥有独立、持久的设备信息。保持稳定身份有助于避免自身反复生成新设备信息，但“设备农场判定”“某字段是最致命信号”等因果解释未经验证。

## 本项目默认做了什么

以下措施**默认全部开启**，每个实例自动生效（新建实例 / 升级实例后）：

| 措施 | 说明 | 开关 |
|------|------|------|
| **唯一且持久的 machine-id** | 每个实例首启生成专属 machine-id，存入数据卷，重启/升级/重建保持不变。 | 恒开 |
| **稳定的 hostname** | 内部主机名采用电脑名称样式（如 `lenovo-pc-372`），从实例 ID 稳定派生。管理面仍以原容器名寻址。 | 恒开 |
| **移除 `/.dockerenv`** | 删掉 Docker 注入的容器标记文件。 | 恒开 |
| **稳定的 MAC** | 使用常见厂商 OUI 和实例 ID 派生的后三段。MAC 本地管理位本身不能证明设备真假，修改 MAC 的风控效果未验证。 | 恒开 |
| **os-release 显示为 deepin** | 改写发行版说明文件，不会改变实际内核、系统包或图形环境；这些信息仍可能被观察。 | `WOC_SPOOF_OS`，默认 1，设 0 后需重建实例恢复原镜像文件 |

实现位置：`docker/woc-identity.sh`（启动钩子 `/custom-cont-init.d/00-woc-identity`，root 身份、在微信启动前执行）+ `panel/server/src/docker.ts`（hostname / MAC / 开关透传，建容器时设置）。

## 手动「重置设备 ID」

管理页保留了重新生成 machine-id 的操作入口。此操作会改变已有设备身份，不能视为解除腾讯账号限制的方法，也不应在正常升级或重连时反复执行：

**管理页 → 该实例卡片 →「安全」→「重置设备 ID 并重启」**

会生成一个新的唯一 machine-id 并重启该实例，之后重新扫码登录。仅对已升级到新镜像的实例可用（旧镜像无设备身份模块，会提示先「升级实例」）。

## 已被标记账号的恢复

- 按微信客户端给出的验证、申诉或重新登录流程处理。项目无法改变服务器侧的账号状态。
- 项目没有可验证的“干净指纹”定义，也没有可靠数据证明更换某个字段能够恢复账号。

## 局限与风险（务必知悉）

- 程序仍能观察内核、图形服务、网络、进程和文件系统等环境信息。已有措施和本 fork 的环境过滤不能保证不可检测。
- 用户报告无法据此推算封禁概率；本项目也没有获得腾讯对远程容器使用场景的授权确认。具体服务约束应查阅腾讯当前协议，不能把“Docker 一定违规”或“用了原版客户端就一定没有风险”写成结论。
- `WOC_SPOOF_OS=0` 后需按新配置重建实例，发行版文件才会恢复为基础镜像内容。修改发行版信息的效果需要实测，不能预设其能解决强制退出。

## 调参

`.env`（复制自 [.env.example](../.env.example)）：

```bash
WOC_SPOOF_OS=1   # 1=伪装成 deepin（默认），0=显示真实 Debian
```

machine-id / hostname / dockerenv 三项沿用上游的固定行为，没有新增开关。本次不迁移持久化设备文件或重置已有实例 ID。
