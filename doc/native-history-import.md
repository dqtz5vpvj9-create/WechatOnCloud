# Windows 历史记录合并到 Linux 原生微信：验证记录

2026-11-11 完成一次同账号、跨版本的实际导入验证：Windows 微信 4.2.0.11 → Linux 微信 4.1.13.26。目标是在 Linux **原生微信**中读取、搜索历史记录及打开现存附件，同时保留云端新消息。以下为一次受控迁移的结果，尚未提供通用的一键导入入口。

## 上游讨论能证明什么

[#121 的维护者回复](https://github.com/Gloridust/WechatOnCloud/issues/121#issuecomment-5828404878)认可手工合并备份的方向，并记录一键导入/导出需求。`WOC_DATA_ROOT` 简化宿主存储位置，不负责数据库格式、密钥或记录合并。

后续[跨网段成功报告](https://github.com/Gloridust/WechatOnCloud/issues/121#issuecomment-6169535573)验证了特定环境下的手机迁移通路。8015/TCP 可达、路由和 NAT 属于手机原生迁移路径，配置见 [chat-migration.md](chat-migration.md)。这份报告没有验证 Windows 数据库直接覆盖 Linux 的兼容性。

## 本次采用的路径

1. 原 Windows 微信保持关闭，完整复制数据库、WAL、配置和媒体。原目录保留。
2. 云端停止实例及重建/解密任务后，制作最新的原始字节备份。所有 SQLite/SQLCipher 连接只打开独立副本；禁止 SQL 打开运行中的源数据库，包括只读连接。运行中验证使用带 WAL 校验、失败即放弃的字节快照。
3. 在副本上校验两端密钥及完整性，保留当前云端消息分片，将历史分片重新加密为目标客户端可读的格式。保留分片内部的消息 ID、账号映射与时间标识。
4. 按会话及服务端消息 ID 去重，重新映射联系人、资源和目录的全局 ID。保留当前会话设置、免打扰和未读状态，历史新增会话的未读数清零。
5. 将现存媒体合并到独立宿主目录，同名异内容文件保留冲突备份。通过实例声明保留挂载，重建继续使用当前镜像。
6. 在客户端关闭时合并 MMKV 年度文件状态。使用腾讯官方 MMKV 独立读取器验证密钥、CRC、元数据长度和全部键值；当前状态优先。不能整目录覆盖其他账号/平台配置。
7. 将候选数据先复制到目标卷内，再通过同文件系统 rename 切换。宿主 `/opt` 与 Docker 卷可能跨文件系统，不能依赖跨盘 rename。
8. 原生微信重新建立文字搜索索引，再做真实界面验证和全量消息身份对比。

### 搜索与附件的现有边界

对切换时 1,820,147 条文字记录检查原生索引，发现 44 条身份缺口：43 条属于迁移前云端数据，原云端索引也没有它们；另 1 条属于 Windows 原始数据，其原 Windows 索引同样缺失。小范围清除原生进度后重新扫描，43 条仍被客户端跳过。记录正文保留，未通过改写内容或来源标志强行建立索引；这些记录的关键词搜索仍未解决。

一张 2019 年图片仅有可显示的缩略图，原图提示失效。两端现有附件树和关联索引均未找到对应原图，迁移工具无法生成缺失的原始媒体。抽测通过的媒体不代表每个历史附件都存在。

### 原生后台重扫的两个发现

- 原生文字索引异步建立，首次搜索无结果需要结合实际覆盖率判断。一次界面搜索成功不足以证明全部记录已索引。
- 合并资源记录后，缺失的原生扫描进度会触发重复资源解析。本次通过单变量测试确认 `FtsRange.range_type=2` 控制该资源处理；最终在最新关闭副本中按消息身份归并重复资源，重映射明细，保留不同类型/索引及最近访问版本，并保留所有扫描进度。`range_type=1` 的重新扫描未补齐上述 43 条旧记录，不能据此承诺修复。

大批量原生索引构建曾触发实例的闲时内存自愈。验证期间临时提高该实例阈值，并设置自动恢复时限；结束后恢复原阈值。未修改永久默认值或内存计算方式。

## 媒体声明与重建

面板内部可选字段 `Instance.historyMedia` 声明账号目录及允许的媒体挂载，仅限：

- `msg/attach`
- `msg/video`
- `msg/file`
- `msg/migrate`
- `business/emoticon`

消息数据库继续放在原实例卷。挂载使用 Docker 结构化 bind；路径缺失时拒绝，避免自动建立空目录。面板删除现有容器前用隔离、只读、有内存和日志上限的辅助容器检查存储目录。配置错误时保留现有实例。辅助容器检查结束立即清理，不增加持久缓存目录。

此字段由受控迁移流程维护，尚未暴露面板编辑/API。手工修改 Docker 运行时挂载仍会在重建时丢失。

## 回滚与数据保护

保留切换前的加密数据库、WAL、认证配置、媒体冲突副本、声明配置和 SHA256 清单。密钥、账号路径、凭据、截图及正文只在私有迁移目录保存，不能提交仓库。

**上线后收到新消息，禁止直接覆盖回切换前备份。** 必须停止实例，重新保存最新数据，将新增消息和媒体与旧数据协调后制作回滚候选，重新验证完整性及消息并集。本次旧备份恢复脚本带上线后拒绝直接恢复的保护。

后续产品化应提供独立暂存、容量预检、进度、冲突报告、关闭实例后的最终增量合并、原生验证及受保护回滚。现有验证不能推广为任意微信版本、账号和平台组合的兼容承诺。
