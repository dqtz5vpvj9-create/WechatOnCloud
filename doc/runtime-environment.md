# 微信启动环境过滤的范围

这项修改减少传给微信进程的容器管理元数据和远程桌面凭据。**它不能清除所有可观察的容器特征，也不能保证避开微信风控或消除账号风险。** 腾讯未公开完整判定规则，本项目没有验证哪些特征会触发哪一种账号处置。

## 已处理的内容

微信通过 `docker/wechat-env.sh` 启动。包装器枚举环境变量名，删除明确属于控制面的项目项，再用 `exec` 启动原来的微信可执行文件：

- `WOC_*`、`VNC_*`、`KASM_*`、`KASMVNC_*`、`REMOTE_DESKTOP_*`、`LSIO_*`、`S6_*`、`S6RC_*`、`DOCKER_*`。
- `CUSTOM_USER`、`CUSTOM_PASSWORD`、`PASSWORD` 以及上列控制项对应的 `FILE__` 秘密文件引用。
- 构建版本、构建日期、远程桌面标题/端口及 PUID/PGID 等已知管理配置。完整名单以 `docker/wechat-env.sh` 为准。

包装器只读取名称，不记录或保存变量值；保留程序参数、PID、退出码和信号语义。QQ、Chromium 和自定义应用沿用各自的启动逻辑。

构建时使用的 `/woc/woc-www-patch.sh` 和 `/woc/woc-ime.pl` 在执行完成后从运行镜像中移除，源文件继续保留在仓库。

微信实例的远程桌面页面标题设置为 `WeChat`。这减少了页面标题中的底座品牌信息，页面标题本身不构成环境隔离。

## 保留的内容及原因

`HOME`、`DISPLAY`、Xauthority、D-Bus、XDG、语言、时区、Qt/GTK 输入法、声音、GPU/GL 和代理配置会原样保留，微信仍需要它们连接桌面和网络。环境过滤只影响微信及其子进程的初始环境；管理面板、VNC 和输入功能继续使用自己的运行配置。

已存在的实例 ID、持久化 machine-id、数据卷和稳定派生的设备信息保持不变。本次不会通过重建随机更换设备身份。[systemd 的 machine-id 文档](https://www.freedesktop.org/software/systemd/man/latest/machine-id.html)也把 machine-id 定义为安装时建立、正常启动中保持稳定的机器标识。

源码、许可证和镜像来源信息保留用于审计和升级。宿主机的镜像标签与源码仓库名称也不属于微信初始进程环境中的变量。

## 仍可观察到的内容

微信和桌面服务仍运行在同一个容器中。这项修改没有增加进程、文件系统或用户隔离：

| 范围 | 仍可能观察到的内容 |
| --- | --- |
| 运行时文件 | `/woc` 脚本、`/custom-cont-init.d` 启动钩子、`/config/.woc-*` 状态、`/config/wechat/.woc-version` |
| 桌面底座 | Xvnc/KasmVNC 文件和进程、Openbox、s6、基础镜像系统包、远程桌面证书 |
| 进程和文件权限 | 在系统权限允许的范围内，其他进程的 `/proc` 信息及 `/run/s6/container_environment` 中的控制配置 |
| 内核和设备 | 内核版本、namespace/cgroup、图形设备、虚拟网络接口、驱动、挂载布局 |
| 网络与账号 | 对外 IP、连接规律、客户端版本、账号在服务器侧的状态 |

因此，“微信进程的环境中没有 WOC/VNC 凭据”不能推出“微信无法读取这些信息”。如需进一步隔离，需要另行设计桌面服务与应用进程的权限边界，并验证输入、剪贴板、音视频和升级兼容性。

上游已有的 hostname、MAC、os-release 处理也没有取得腾讯对风控效果的确认；本次保留其兼容行为，不能把上游的经验解释当作腾讯公开的判定机制。

## 验证

无需 Docker 的进程测试：

```bash
python3 -m unittest discover -s docker/tests -v
```

测试覆盖管理变量去除、功能变量保留、特殊参数、退出状态、PID 和 SIGTERM/SIGINT，以及只对微信启动链应用过滤。它验证包装器行为，不验证真实微信登录、音视频或风控结果。
