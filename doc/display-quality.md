# 全局画质

主页、实例桌面的现有顶栏提供“画质：标准／高清”，管理 → 系统提供同一设置。管理员修改，所有已登录设备读取同一服务端设置；本地页面立即刷新状态，其他设备每五秒同步，重新聚焦时立即检查。WeFlow 应用切换保持在侧边栏。

标准使用 1× 画布和 96 DPI；高清使用 2× 画布和 192 DPI。使用 KasmVNC 自带的固定分辨率和缩放消息接口，保留远端鼠标坐标映射，不覆盖浏览器 devicePixelRatio。单帧限制为 16,777,216 像素，单边最大 8192 像素，超大视口按比例收敛。

微信启动时缓存缩放比例，因此切换前要求确认保存编辑内容，随后异步配置两个显示会话并温和重启原有应用进程。整个流程不打开微信数据库，不重建容器，不改变实例镜像。应用未恢复时报告失败并尝试回退；标准模式是默认值。设置与账号文件一起原子持久化；面板重启会对账配置，仅在设置不一致时重启应用。

XSETTINGS 的 Xft/DPI 单位为 DPI×1024：标准为 98304，高清为 196608。兼容脚本只修改已知 autostart DPI 段，保留字体选择；不兼容脚本会明确拒绝切换。持久化文件仅为 /config/.woc-display-quality 和现有 XSETTINGS 配置，使用原子覆盖，无增长队列。

验证：隔离容器中真实微信登录窗口在标准为 280×380、高清为 560×760；真实 WeFlow 的 devicePixelRatio 在重启后分别为 1 和 2。Chromium 和 WebKit 均验证真实 KasmVNC 的 1×/2× 往返切换及鼠标坐标。测试容器使用空配置及应用安装文件，不挂载现有账号数据。

UI 回归：在 desktop 执行 `npx e2e run --config e2e.panel.config.ts tests-panel/display-quality.e2e.ts`。真实 KasmVNC 检查需要独立测试容器的 HTTP 端口 19455，并设置 WOC_HDPI_LIVE=1；未配置时该项明确跳过。
